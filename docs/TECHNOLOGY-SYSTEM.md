# Система технологий

13 октября 2026. Прямое поручение пользователя: UI по четырём референсам, изучение технологий, действующие эффекты для реализованных систем (прежде всего улучшения зданий), остальные эффекты разрешено отложить. Нужна основа адаптивных весов. База выбрана пользователем: `3a226bf`; отдельная ветка `feature/technology-system`. Общая ветка и другие рабочие копии не изменяются.

## Поведение и границы

Пользователь подтвердил полный пул обычных технологий с отложенными неготовыми эффектами; прогресс сохраняется внутри каждой технологии. Прямое уточнение: «перепроизводство не откладывается» — избыток сверх стоимости при завершении теряется. Source tier gates: 6 технологий предыдущего уровня; без реализованных лидеров применяется исходный `TECH_RESEARCH_NO_LEADER_PENALTY = -0.25`, без придуманного руководителя/бонуса. Стоимость империи, native скрытые правила и неизвестные условия явно отмечаются по покрытию.

- Три независимых направления: физика, общество, инженерия. Сервер хранит выбранную технологию, прогресс каждой начатой технологии, изученные определения и устойчивый набор предложений. Нет автоматического выбора при завершении. Переключение сохраняет прогресс; открытие/закрытие UI не обновляет предложения.
- Исходные IDs, стоимость, prerequisites, категории, tier, rarity, potential и weight берутся из локальной 4.5.2, установка только для чтения. Неизвестные условия не заменяются `true`: публикуется причина недоступности зависимого контента. Пул и численные неизвестности уточняются до зависимой реализации.
- На границе месяца используется согласованная в PLANET-BASIC-ECONOMY формула: выпуск науки R после скорости и предыдущий резерв S; при активном исследовании расход резерва `min(S,R)`, прогресс `R+min(S,R)`. Без выбранной технологии выпуск копится. Повторный месячный sink или расход нового выпуска как старого резерва запрещён. Завершение и баланс публикуются атомарно. Избыток прогресса сверх стоимости теряется по прямому ответу пользователя; следующая технология автоматически не запускается.
- Выбор до старта, чужим игроком, наблюдателем, при устаревшей revision, неизвестном направлении/ID или вне предложений отклоняется. Повтор commandId следует существующей идемпотентности сессии. Отключение обычного игрока не прекращает исследование. Пауза не запрещает выбор, но прекращает время.
- Изученный набор передаётся в актуальный ConstructionContext при quote, заказе и ежедневной проверке. Upgrade сохраняет старые jobs/effects/upkeep до атомарной замены в том же slot/zone; отмена оставляет старое здание, возврат по существующим правилам. Проверяются исходный upgrade edge, target prerequisites/potential/allow и совместимость зоны. `can_build=no` относится только к новой стройке. Неподдержанные эффекты технологий явно помечены отложенными, не применяются фиктивно.

## Веса и предложения

Разделить eligibility, вычисление веса и выбор без повторений. Контекст весов задаёт сервер: изученные технологии, подтверждённые факты империи, предыдущие варианты и подключаемые правила. Source `weight_modifier` и previous-option multiplier должны иметь явный статус покрытия; неизвестные native зависимости не выдаются за реализованные. Не добавлять произвольные бонусы за дефицит/стиль игры. Один seed/state на империю, обновление предложений только по игровому событию; reconnect не даёт переброса.

Пользователь подтвердил формулу повторяемых технологий прототипа: `base cost + cost_per_level × число завершённых уровней`; первый уровень стоит base. Это human rule, а не доказательство скрытой native индексации. Каждый уровень завершает отдельное исследование, следующий выбирается вручную; source `levels` ограничивает число повторов, `-1` означает отсутствие предела. `weight_groups` и `mod_weight_if_group_picked` изменяют веса оставшихся карт при выдаче по комментариям исходных скриптов. Прогресс следующего уровня начинается с нуля, избыток теряется.

## UI и сетевой контракт

DOM поверх карты: компактное окно слева с тремя цветными секциями (синяя/зелёная/янтарная), названием/прогрессом/месячной скоростью/резервом; кнопка выбора открывает соседнее окно карточек. Карточка: название, категория, стоимость, эффекты и статус их применения. Отдельный список изученного с фильтром направления. Закрытие окна и Escape не меняют исследование. Уведомление о завершении остаётся видимым до выбора нового. Не создавать фиктивного руководителя исследований или неработающие policy/auto-research кнопки.

Сетевой снимок получает optional `research` с состояниями доступных POV; общий наблюдатель видит read-only состояния, player POV — соответствующую империю. Клиент не рассчитывает авторитетный прогресс, eligibility и случайный выбор. Для команд использовать существующие ACK/pending/error/stale состояния. Устойчивые data-testid и keyboard controls; проверка 1920×1080 и 1366×768. Оригинальные изображения не сохранять в Git; отсутствие импортированной иконки явно допускает текстовую карточку, не изображение из другой технологии.

Дополнение пользователя: настоящие иконки технологий обязательны. Source explicit `icon` либо canonical technology ID определяет `gfx/interface/icons/technologies/<icon>.dds`. Сервер передаёт только относительный путь/длину/SHA-256; клиент читает собственный уже выбранный read-only directory, проверяет metadata и декодирует существующим DDS-reader. Иконки загружаются по запросу в bounded memory cache, без постоянного кеша/upload/server asset delivery. Замена источника/очистка входа освобождает blob URL; stale async result не меняет новую перспективу/источник. Отсутствие/ошибка/нехватка доступа даёт явную подпись, не случайную иконку. Начальный режим отдельных File snapshots не предоставляет доступ к дополнительным файлам: UI предлагает выбрать папку игры для иконок. Основной manifest M3 не расширяется сотнями обязательных иконок, используются отдельные проверяемые metadata технологий.
