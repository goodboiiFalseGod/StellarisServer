# Безопасная перестройка чатов

13 октября 2026. Пользователь разрешил после завершения текущих работ перестроить чаты, инструкции и документацию для экономии контекста, временно выключить автоматизированные рабочие чаты и затем обязательно возобновить работу. Подтверждено: игровой код и архитектура в эту перестройку не входят.

## Текущая граница

Автоматическое развитие через `stellarisserver-m3` приостановлено; тот же heartbeat временно обслуживает только передачу координации. Два старых монитора остаются приостановленными. Независимая проверка будущего патча Stellaris к проектной координации не относится. Исходная конфигурация development-монитора сохранена локально в игнорируемом `artifacts/context-maintenance/previous-monitor.json` рабочего каталога этой задачи; не публиковать её как проектную конфигурацию.

Координатору, интегратору, QA и UI передано поручение безопасно завершить только текущий атомарный цикл, сохранить собственную работу, дать краткий handoff и ждать. Интегратор может закончить уже начатый цикл с его владельцами. Никаких новых задач и возобновления старого мониторинга до передачи.

## Условия передачи и продолжения

1. Через компактные статусы проверить завершение четырёх владельцев из CONTEXT-HANDOFF. `idle` само по себе недостаточно: нужны итоговые результаты, оставшиеся изменения/блокеры и подтверждённая остановка новых назначений. Не прерывать активный код, ревью или QA.
2. Проверить фактические ветки/коммиты и чужие изменения. Сохранить точные итоговые handoff со ссылками на отчёты; не считать незаконченные ветки потерянными или автоматически интегрированными.
3. Обновить CONTEXT-HANDOFF кратко по результатам. Сохранить решения, исследования, экспериментальные ветки и ручные gates. Удалять код, менять архитектуру или выдумывать правила нельзя.
4. Свежий координатор `01a132e0-2d0c-7fc0-997d-d007f3397592` принимает координацию. Передать интеграцию в один свежий короткий чат; QA и небольшие реализации запускать как ограниченные задачи с кратким контекстом по принятой политике. Сохранить владельцев/настройки референса, численных исследований и ручной приёмки. Не менять модели/effort.
5. После подтверждённой передачи можно архивировать завершённые старые чаты координации/интеграции/UI/QA; оставить ссылки и возможность восстановления. Не архивировать действующую работу или источники незавершённого результата.
6. Перенаправить **тот же единственный** heartbeat `stellarisserver-m3` на свежего координатора с кратким актуальным заданием и ссылками на контракты. Возобновить разрешённую работу, проверить получение первого задания новым владельцем. Не оставлять проект просто на паузе и не создавать дублирующие мониторы.

На время ожидания тот же heartbeat может будить только чат обслуживания `01a132d5-b4fc-7b13-a258-3b6cc7dca57a`: проверять завершение владельцев и выполнять этот переход. Он не назначает новую разработку до соблюдения условий. После передачи heartbeat возвращается к разработке; отдельный монитор обслуживания не нужен.

## Приоритет, который нужно сохранить

Основной следующий результат — меню планеты, близкое архивному референсу по UI **и функциональности**, включая обзор, районы/зоны/здания, особенности/блокеры, jobs и подтверждённую очередь/стоимость/прогресс/отмену. Детали населения ниже по приоритету. Флот и навигация остаются частью полного этапа. Устаревшие поля ввода координат убрать из UI с сохранением авторитетных map orders; дальнее отдаление системы возвращает галактику, приближение галактики не входит в систему автоматически. Точный порог перехода не придумывать.

Сначала завершить активный исправляемый QA-цикл. Затем — следующий подтверждённый независимый шаг меню планеты. Startup/effects/placement и неизвестная арифметика блокируют лишь зависимые операции; никаких поддельных enabled controls, отвергнутой лаборатории или подавления экономики. Все остальные ограничения и порядок fallback — DECISIONS и тематические контракты. Готовность объявлять только по проверенному стабильному checkout с явными ограничениями.
