# M3 — изолированное ядро пространства

Инженерный этап после статического preview, до сетевого v2. Реализует только согласованные [время/приказы](M3-TIME-AND-MOVEMENT.md) и [fixture N01](M3-WORLD-FIXTURE.md). Не меняет GameSession/M2, HTTP/WebSocket, экономику, AI или баланс. Не объявляет визуальный Chrome gate закрытым.

## Границы и данные

Новые типы в Stellaris.Session/M3; отдельный console-check проект tests/Stellaris.M3Checks без новых пакетов. Состояние мира неизменяемое: определения и списки копируются/закрываются read-only, команды и дневной расчёт возвращают новое состояние. Ошибка оставляет исходный объект полностью прежним. Это staged-кандидат для будущей атомарной публикации вместе с экономикой, не замена ECS целевой игры.

CreateFixture принимает два разных положительных participantId; порядок соответствует player-slot, не номеру подключения наблюдателя. Стабильные ID: S01…S16; body `star:S01`/`planet:S01`, стартовые `station:S01`/`station:S16`, `colony:1`/`colony:2`, `fleet:1`/`fleet:2`; hyperlane `S01-S02` с ordinal-упорядоченными концами. Они непрозрачны для клиента, не должны парситься для авторизации. В изолированном fixture economyPlanetId=1/2 — логические слоты, НЕ EntityId экономического ядра. Сетевая проекция обязана явно заменить их фактическими Planet.Index владельцев (при стандартном порядке создания M2 это 1/4); не выдавать слот 2 как ID второй планеты. Публичные данные и визуальные ключи — существующий spatial-контракт. Visual scale на этом этапе технически 1; внешняя подгонка размера графики не влияет на навигацию.

Календарный helper принимает неотрицательный целый elapsedDay, выводит year/month/day и completedMonths по 12×30, checked overflow отклоняется. День 0 = 2200.01.01. Pure spatial AdvanceDay получает текущий целый день и возвращает состояние на день+1; календарь/экономика пока не публикуются. Фазы и моменты binary64, N01 неизменен.

SpaceWorld хранит собственный immutable ElapsedDay (первоначально 0); команды берут моменты фаз из него. Если AdvanceDay также принимает expected currentElapsedDay, несовпадение отклоняется до расчёта: caller не может случайно отмотать/перескочить фазы. Это техническая защита staged-кандидата, не второй независимый игровой календарь.

## Приказы и безопасность

MoveToPoint/MoveToSystem/Stop получают participantId и явный разрешённый набор систем. Чужой/несуществующий флот, скрытая/несуществующая система — единый OUT_OF_SCOPE; неверная конечность/радиус — INVALID_TARGET, неверная фаза — INVALID_PHASE, отсутствующий путь — NO_ROUTE. Typed exception содержит безопасный code/message, без перечисления скрытых ID. Новая валидная команда увеличивает orderVersion checked; idempotency commandId остаётся обязанностью будущей сессии, не дублируется в pure ядре.

Кратчайший BFS проходит только разрешённые системы; соседи ordinal-сортированы. Все определения/ссылки проверяются при создании, совпадающие центры/дубликаты/неизвестные концы отклоняются. Нулевая дистанция завершается сразу, без NaN. Цель в текущей системе останавливает маршрут. Подготовка отменяется stop/локальным приказом; inTransit допускает только pending stop/межсистемную замену. Pending-цель валидируется на принятии и повторно после прибытия; последняя валидная pending-команда побеждает, неверная не портит прежний приказ.

AdvanceDay получает разрешённые системы для каждого владельца (явный callback без сетевых обращений) и расходует ровно dt=1 между фазами, не теряя остаток дня. Перед новым сегментом маршрут перепроверяется; потерянная видимость/связность останавливает флот в доступной граничной позиции. Уже начатый transit завершается физически, но скрытые endpoints позднее вырезает проекция. Нулевые фазы ограничены числом допустимых переходов; патологическое состояние даёт видимую ошибку, не бесконечный цикл. Внешняя пауза означает отсутствие вызова AdvanceDay. AFK не меняет pure-приказ.

Граница при утрате разрешённого маршрута: уже начатый approach заканчивается у exit и переходит в idle без charging; уже начатый charging заканчивается у exit без отправления; transit заканчивается у entry. Не телепортировать флот в начало фазы. Pending destination проверяет BFS от destination текущего transit уже при принятии (NO_ROUTE не затирает прежний pending), а затем повторно после прибытия. Это раскрывает существующие правила отказа недостижимой цели и остановки на границе фазы.

## Приёмка

16/24 topology, 34 bodies/2 colonies/2 fleets по три корабля, player-slot не зависит от observer ID. Calendar day0/29/30/359/360 и invalid/overflow. Локальное точное прибытие/ноль/замена/радиус/NaN/чужой ID, BFS S01→S16 шесть рёбер с ordinal tie-break, изолированная разрешённая цель NO_ROUTE. Все пять фаз, дробный остаток approach→charge→transit→entry, stop/replace во время transit, текущая destination, потеря видимости маршрута. Любой отказ не меняет исходное состояние/коллекции; caller не может изменить мир через возвращённые списки. Повторные вычисления дают одинаковые значения на текущей платформе; cross-platform bitwise пока не заявляется. M2 regressions сохраняются.

Следующий, отдельный этап: M3Session с монотонными deadline, commandId cache, атомарным днём/месячной экономикой и фильтрованными v2 DTO. Транспорт и точный профиль запуска фиксируются отдельно до кода.
