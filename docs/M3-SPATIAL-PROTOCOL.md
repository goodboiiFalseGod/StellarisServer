# M3 — пространственная проекция и команды

Статус: технический контракт будущей реализации, не работающий protocol. Раскрывает согласованный срез; точные численные параметры мира/движения остаются в [контракте времени](M3-TIME-AND-MOVEMENT.md). M2 protocol=1 сохраняется как отдельный лабораторный режим; M3 использует protocol=2, несовпадение версии явно отклоняется, не трактуется как v1.

## Транспорт и ограничения

Сохранить ASP.NET Core/.NET 8, WebSocket JSON UTF-8, полные разрешённые snapshots, same-origin, без сжатия/дельт и без внешнего скачивания игровых ассетов. M3 слушает только loopback; LAN/публикация не входят. Точные профиль запуска/URL фиксируются перед серверным кодом; запуск M3 не должен молча менять контракт M2.

Наследуются защита Origin, join code, heartbeat 10 с/timeout 30 с, join timeout 10 с, не более 8 соединений/20 команд в секунду на соединение, commandId 1..64, не более 10000 уникальных ID участника. Клиентская очередь ≤100, отправка ≤8 команд/сек. Токены не передаются в URL, в общий snapshot и в логи. Все ограничения являются частью реализации v2, а не предположением, что старый v1 уже покрывает новые поля.

Технические предохранители v2: входящее сообщение ≤16 KiB, исходящий snapshot/manifest ≤1 MiB каждый; превышение явно диагностируется, не усечение JSON. Send loop один на соединение, ≤5 snapshots/сек; непрочитанное состояние заменяется новым, команды/ACK не теряются молча. Если клиент не читает ограниченную очередь ответов, сервер разрывает соединение без задержки симуляции. Реальные размеры измеряются на M3; стресс 200 drawable-корветов не требует 200 полных экономических объектов в snapshot.

## Manifest и готовность

`GET /m3/asset-manifest` возвращает только versioned metadata: schemaVersion, profileId, profileDigest, gameVersion, importerVersion, materialProfileVersion, files[{relativePath,byteLength,sha256,kind}], visuals[{visualId,dependencies,materialProfile}]. Порядок полей/хеширования фиксируется перед importer-кодом. Это публичный профиль ассетов, не hash игрового мира. Никаких оригинальных байтов, абсолютных путей, серверных файловых endpoints или произвольного запроса пути.

`join` v2 сохраняет поля v1 с protocol=2. `welcome` возвращает собственные participantId/token/sessionId и требуемые profileId/profileDigest. Новая сессия/профиль сбрасывает локальную готовность импорта; token не подтверждает доступ к ассетам.

Команда `assetReady` содержит commandId, profileId, profileDigest, ready. Готовность привязана к текущему WS-соединению, не к token: каждое новое соединение начинает с ready=false. Сервер проверяет профиль; ready=false снимает готовность участника в лобби. Для `ready:true` и запуска оба игрока должны быть online, текущие соединения подтвердили импорт и игровые настройки сохранили. Это UX-контракт, не доказательство владения файлами; сервер не доверяет ему при проверке команд. Наблюдатель получает пространственную проекцию только после разрешения хоста; графическое представление открывает после собственного импорта. Pending observer не получает мир.

При reconnect в ту же sessionId набор в памяти страницы сохраняется, но клиент повторно подтверждает digest на новом WS новым commandId; replay старого assetReady не должен включать готовность нового соединения. После reload — новый импорт и подтверждение. Живая сессия не останавливается из-за загрузки клиента; его игровые команды до assetReady отклоняются, heartbeat/возврат доступны. При уже загруженном наборе отзыв OS-разрешения не сбрасывает assetReady текущей сессии; новые чтения требуют разрешения.

## Проекции v2

Сохраняются участники, каталог M2, собственная экономическая `planets[]` и поля produced/jobUpkeep/buildingUpkeep/upkeep/net. Чужая колония не добавляется в экономический массив из-за видимости её модели. Наблюдатель получает обе экономики. `month` остаётся числом закрытых экономических месяцев; календарь передаётся отдельно. Лабораторные `speed` и `step` v1 не переосмысливаются внутри protocol=1.

`state` v2: protocol, sessionId, sequence, phase, tick, elapsedDay, date{year,month,day}, month, paused, speedDaysPerSecond, you, participants[], planets[], catalog, assetProfile{profileId,profileDigest}, spatial, lastError, lastTickMilliseconds. tick растёт только при успешном дневном шаге; sequence — при любом опубликованном изменении. `lastTickMilliseconds` измеряет весь день, не только месяц.

| Поле spatial | Содержимое |
|---|---|
| systems[] | id, name, galaxyPosition{x,y,z}, radius, starBodyId? только при разрешённом body |
| hyperlanes[] | id, fromSystemId, toSystemId; только разрешённые концы |
| bodies[] | id, systemId, kind(star/planet/station), name, localPosition{x,z}, visualId, scale; опциональная публичная метка владения |
| colonies[] | id, bodyId, ownerParticipantId, economyPlanetId только при доступе к экономике; связь не требует неподвижной планеты в будущих этапах |
| fleets[] | id, ownerParticipantId, name, visualId, shipCount, phase, location, movement |

Новые spatial ID — непрозрачные строки, уникальные в sessionId и не переиспользуемые после удаления. Численные planetId/participantId M2 не переименовываются в spatial ID; явная связь economyPlanetId предотвращает путаницу. Серверное владение империей не выводится из строковой метки на модели.

`location` — строгий union: system{systemId,position{x,z}} либо transit{fromSystemId,toSystemId,progress}. Transit не имеет фиктивной localPosition или «текущей системы». Progress задаётся сервером в [0,1]. `movement` для владельца/наблюдателя: orderVersion, target, routeSystemIds[], phaseStartedDay, phaseEndsDay?, pendingAction?. Другим игрокам — только публичная фаза/позиция, без приказов/очереди/секретной цели. Состав будущих кораблей и боевые характеристики этим DTO не обещаны.

Полный snapshot заменяет предыдущую разрешённую spatial-проекцию. Отсутствующая сущность удаляется из локального представления/выбора, но клиент не объявляет её уничтоженной: причина может быть в видимости. Проекция не оставляет ссылки на скрытые ID через route, endpoints, colony links или ошибки. Если endpoint transit скрыт, весь fleet transit исключается из проекции этого получателя, а не получает скрытый ID/ложную позицию; приватное серверное состояние остаётся. Если скрыт связанный body/colony, соответствующая опциональная ссылка отсутствует, не содержит dangling ID. В разрешённом игроку графе маршрут не строится через скрытые системы. Тестовый известный мир не отключает фильтр.

## Команды

| type | Аргументы | Результат |
|---|---|---|
| moveFleetToPoint | fleetId, systemId, x, z | Валидация владения/видимости, текущей системы, конечных чисел и границы; новый локальный приказ |
| moveFleetToSystem | fleetId, targetSystemId | Валидация цели/связности; маршрут строит сервер, pending-замена во время transit |
| stopFleet | fleetId | Немедленная остановка либо pending stop во время transit |
| stepDay | нет | Хост, running, paused; один атомарный день |
| speed | speed:1\|2\|4 | Хост; дни/сек только в v2 |

Остальные команды configure/ready/start/setJobs/pause/transferHost/approveObserver сохраняют смысл и ограничения M2, с добавленными проверками assetReady для игровых мутаций. Команда `step` v1 в v2 отклоняется с объяснением использовать stepDay, а не продвигает месяц случайно. commandId обязателен, отправитель определяется сессией, не ownerId из payload. Неизвестные поля/типы и слишком большой/нечисловой payload отклоняются без мутации.

`result` v2: commandId, accepted, code, message, commandSequence?, appliedTick?, stateSequence?. ACK принятого move подтверждает установку приказа, не прибытие. Принятые на паузе приказы не продвигают позицию; appliedTick отражает текущую границу. Повтор ID/того же payload возвращает первоначальный result без нового приказа/движения; другое содержимое — ID_CONFLICT. OUT_OF_SCOPE одинаков для чужого/скрытого/несуществующего объекта, без деталей. Остальные коды: INVALID_COMMAND, INVALID_PHASE, ASSETS_NOT_READY, PROFILE_MISMATCH, INVALID_TARGET, NO_ROUTE, RATE_LIMITED. Конкретный code не должен раскрывать невидимую цель.

## Клиент и приёмка

Применять только свою sessionId и возрастающую sequence; вернуть свежий полный snapshot после разрыва. До свежего snapshot команды движения недоступны. Рендер интерполирует только разрешённые серверные состояния/сегменты; не вычисляет собственный путь или результат прибытия. При паузе/reconnect/смене orderVersion/context loss не продолжать старую анимацию вслепую; синхронизироваться с фактическим состоянием. Точный буфер интерполяции и тайминг UI фиксируются до клиентского кода.

Тесты: version mismatch, join/ready без импорта, профиль изменился, reload/reconnect, pending observer, чужой/скрытый ID, route-ссылки на скрытые сущности, отсутствие чужой экономики и токенов, повтор команд во всех фазах, неполные/лишние поля, snapshot limit, slow reader. Проверить клиент v1 против режима v1 без регрессии; старый клиент не подключается к v2 с молчаливо изменёнными единицами времени.
