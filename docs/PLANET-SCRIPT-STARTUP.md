# Реализация стартовых зданий из скриптов 4.5.2

## Объём

Первый частичный атом связывает подтверждённые стартовые эффекты Stellaris 4.5.2 с M3-сессией. Для явно выбранного обычного пресета сервер импортирует homeworld initializer pool, выбирает исходный class/size и выполняет поддержанные эффекты зданий в порядке dispatcher. Районные группы и здания становятся неизменяемым фактическим графом колонии и доступны владельцу и observer с выбранным player POV только для чтения. Установка игры читается без изменений и не копируется в Git.

Обычные входы — три существующих пресета `economic`, `scientific`, `military` с их выбранными этиками и civic. Hive/machine контексты можно принимать только от caller, который явно передал authority/ethics/civics; этот атом не добавляет им пресеты и не изобретает civics. Сессии без поддержанного выбранного пресета сохраняют прежнее поведение без заявления, что native startup был выполнен.

## Источник, порядок и модель

Использовать порядок `generate_start_buildings_and_districts` из `common/scripted_effects/01_start_of_game_effects.txt` и достигнутые authority/ethic/default-origin/civic effects. Выбранный `origin_default` исполняется на позиции dispatcher. Для трёх поддержанных ordinary presets source facts заданы явно; неизвестный достигнутый predicate или effect без evaluator приводит к отказу и не публикует authoritative plan. Другие origin либо пропускаются при несовпадении входного origin, либо дают source/effect-specific gate при совпадении. Hive/machine сохраняют прежний typed partial path с явными gates для неизвестного контекста. Подсчёты и условия извлекаются из исходника, а не дублируются как runtime layout policy. Сохранять hashes и provenance.

Один occurrence района задаётся на district definition; его source-count materializes как level. До упорядоченных стартовых effect-ов движок создаёт один уровень source-selected district с `default_starting_district = yes`; для обычного continental это `district_city`. Затем authority source effect добавляет ещё два city, значит в DTO итоговый city level 3. Это прямое правило пользователя; импортировать source-selected district type, начальный level задаётся этим engine rule, не прошивать итоговое число. У occurrence есть явные zone-slot occurrences с source type/slot number, зоны и здания принадлежат этим occurrences. Не создавать отдельный район на каждый level и не использовать definition ID как instance ID. `add_district_and_planet_size_if_needed_effect_amount` — scripted effect в `common/scripted_effects/01_start_of_game_effects.txt:4624` и исполняется по его телу: повтор count, проверка `free_district_slots`, иначе увеличение размера при `planet_size < 25`, затем `add_district(ignore_cap=yes)`. Прямое решение пользователя задаёт общий capacity: `planet_size + применимые общие модификаторы capacity`; свободные места — capacity минус сумма уровней установленных групп. Пересчитывать после каждого добавления и увеличения размера. Держать общую capacity отдельно от district-type `max_add`, `max_mult`, `is_uncapped` и shared pools; импортировать только source-доказанные модификаторы. Специфические неподдержанные модификаторы явно ограничить согласно разрешённому базовому срезу.

Обычный старт добавляет `building_capital` без адреса до двух city-add effects. При принятом инварианте одного district group на definition, `slot_city_government` и `zone_default` образуют единственную совместимую цель capital. Совместимость остальных безадресных обычных зданий выводится из `building_sets`, zone `include/exclude` и фактических zone instances. Это правила представления occurrence graph, а не native instance IDs. Для районов, уровней, слотов, зданий, зон и features генерировать собственные стабильные в пределах графа instance IDs. Поддерживать упорядоченный source effect sequence; не откладывать операцию через промежуточную проверку здания, если это меняет наблюдаемость. Форму helper-а проверять по конкретным source operands: изменившийся порог, предел размера, шаг, параметры district add или порядок ветвей отказываются.

Не принимать неизвестные операторы/достигнутые эффекты, missing/changed/malformed source, недостающие required context facts и неоднозначные цели как успешный layout. Variable mutations и modifiers без evaluator остаются явными gates и не объявляются вычисленными. Хранить raw job/level modifiers без перевода их в числа попов. Не генерировать native base levels, если их нет в разобранных source effects.

## Runtime и проекция

Реальный `M3Server` передаёт проверенный импортированный startup plan в session; ошибка required startup source останавливает запуск сервера и не превращается в legacy lab fallback. Все три поддержанных ordinary preset завершают фактические rural effects без rural/origin/default-placement gates. Выбранный preset при `start` создаёт actual immutable installed-instance graph, включая deposits/blockers и их ссылки, district caps, districts, zones и buildings. Владелец и observer с выбранным player POV получают его в read-only development projection; observer general/pending view, другой игрок и чужие colonies не получают private graph. Сам граф не включает строительные команды, очередь, экономический scheduler, employment или расчёт demography.

Геометрия текущей M3 fixture остаётся прежней. Полный galaxy startup, solar mapgen, pops/AI/demographics, все special origins/civics и полная экономика остаются вне атома и показываются как явные ограничения.

## Приёмка

- Импорт текущего 4.5.2 источника сохраняет относительные пути/hash/provenance; required missing/changed/malformed source и неподдержанный достигнутый operator дают видимый отказ.
- Поддержанные ветви ordinary/hive/machine сохраняют source order, включая authority swaps и поддержанные ethics/civics; counts берутся из expanded source operations.
- District count отражён как level одного definition-group; slot occurrences и graph immutable. У capital единственная совместимая government target либо точный отказ.
- Для каждого неизвестного входа helper отказ локализован до конкретного effect и поля context. Никаких guessed стартовых чисел/ветвей.
- Реальный selected-template M3 start использует граф; owner projection и разрешённый observer-player projection получают owner graph, pending/foreign projections — нет. Пустой template и старые constructors сохраняют legacy путь.
- Узкие проверки покрывают source ветвление/порядок, malformed/unsupported/missing facts, source mutation, capital target, graph immutability, player/observer privacy и legacy callers.

## Ограничения

Эта поставка не означает завершение запрошенного planet menu. Специальные условия контента, source-derived job capacities/employment, quotes/build commands, monthly scheduler, AI, solar mapgen и ручная UI приемка остаются отдельными работами. Тесты и интеграционная сборка не доказывают readiness stable main.

## Source-world: ordinary continental M3 presets

Атом для `economic`, `scientific`, `military` восстанавливает фактическую обычную continental цепочку старта: упорядоченные deposits/blockers из `generate_start_deposits_and_blockers`, скрываемые залежи по `blocker_swap_types` и source `drop_weight`, их district-cap modifiers, затем `rural_districts_initializer`, `origin_default` и `rural_districts_placement`. Это применяется к actual M3 start и возвращается в immutable owner/observer-player DTO; обычные безадресные здания получают zone compatibility из imported `building_sets`, zone `include/exclude` и реальных zone instances. DTO показывает explicit zone instances/links. Все три пресета проходят source rural path без rural/origin/default-placement gates.

При blocker placement связанная source-залежь скрывается; blocker без source swap list остаётся standalone и не получает выдуманной пары. Каждый установленный blocker даёт −1 общей районной вместимости по прямому решению человека. `free_district_slots = size + active general-capacity modifiers − сумма районных levels`. Type-specific source caps вычисляются отдельно по активным/скрытым deposits и source-defined modifiers, с live helper пересчётом после каждого добавления и роста размера. Не подменять порядок source effects фиксированными итоговыми списками. Weighted choices воспроизводимы от собственного seed; идентичность native PRNG/full solar geometry не требуется. Кандидаты и их веса берутся из blocker `blocker_swap_types`/`all_blocker_swap_types`, `use_weights_for_blocker_swap_types` и deposit `drop_weight`; не выбирать первый вариант и не вводить веса вручную. Повторяющиеся цели учитываются как повторные occurrences; при отсутствии допустимой цели, дубликате неоднозначного definition или неподдержанном/неразобранном весе — явный отказ.

Внешние contracts сохранения остаются immutable, provenance hashes включают реально прочитанные required source files, но source bytes не попадают в M3 DTO. Пресетный runtime использует предварительно импортированные immutable plans, а не читает установку под lock сессии. Session seed выбирает initializer/size; blocker weighted choices используют детерминированный seed по `(template, size)`, так что одинаковый template/size воспроизводит одинаковые blockers. Это ограничение прототипа и не заявляет identity native PRNG; отдельный seed-specific materializer остаётся будущей работой. Hive/machine остаются на прежнем typed partial path и явно сообщают omitted context; ordinary facts не переименовываются в их aliases. Обычная organic population даёт 1 base Workforce на поп; trait Workforce bonuses считаются отдельно в последующем runtime jobs atom. Этот атом не включает jobs, экономику, lifecycle строительства, полный solar geometry или новый-save gate.
