# Любое положительное число игроков M3

Прямое поручение пользователя 16 октября 2026 заменяет ограничение двумя игроками в M3. Применяется к текущему графическому прототипу и его тестовым fixture; экономику, импорт и механику движения не меняет.

- Лобби принимает одного или более игроков без фиксированного лимита мест/соединений. Каждый получает собственные participant/country/planet IDs и пресет. Наблюдатель не занимает место игрока.
- Каждый игрок подтверждает текущую ревизию настроек/состава. Хост запускает подготовку только при готовности и подключении всех игроков. Нулевой состав, неготовый, отключённый или устаревший голос блокируют старт. Изменения настроек/состава по прежнему контракту сбрасывают согласия.
- Одна человеческая команда старта генерирует мир с домашним миром, колонией, станцией и флотом для каждого игрока. После подтверждения текущих fingerprint/profile всеми игроками сессия автоматически переходит в running. Повторные человеческие Ready/Start не требуются; наблюдатель не блокирует запуск. Старый/чужой профиль не учитывается.
- Диапазон AI-империй сценария не ограничивает число человеческих слотов. Физическая верхняя граница — число систем сценария: нельзя создать отдельные домашние системы для большего состава. Невместимый состав/ошибка размещения дают явный отказ до публикации мира, без отбрасывания игроков. Ресурсы сервера и прежние лимиты сообщений/очередей сохраняются; бесконечная нагрузка не обещается.
- ID владельцев и соответствие economy/spatial/startup сохраняются для всех. Игрок получает свою приватную экономику, наблюдатель видит разрешённые общую/персональную проекции и остаётся read-only. Передача хоста — любому другому подключённому игроку. После старта переподключение возвращает прежнего участника, новый игрок отклоняется; в лобби отключение освобождает место по [правилам состава](M3-LOBBY-MEMBERSHIP.md).
- Legacy fixture для одного/двух игроков сохраняет 16 систем; два старых старта S01/S16 и их IDs неизменны. Дополнительные игроки занимают свободные системы, при необходимости квадратная сетка расширяется. Системы не разделяются несколькими стартами. Это тестовый мир, production использует генератор.

Приёмка: 1/2/3/10/20 игроков проходят полный цикл ревизия→Ready→generation→asset ACK→running, шаг и возврат. Проверить, что последний неготовый/отключённый игрок и последний неподтверждённый импорт блокируют нужный этап; наблюдатель не влияет. Проверить число/уникальность домашних миров и владений, фильтрацию приватных данных, отказ позднего входа, невместимый состав и сохранение старого двухигрового сценария. Выполнить focused session/generation/client и реальные HTTP/WebSocket-проверки; браузером проверить одиночное лобби. Нагрузочную вместимость сверх проверенного состава отразить отдельно.

## Сетевой бюджет исследований

Неизменная source-проекция переиспользуется по паре participantId/sequence, чтобы фоновые отправки на паузе не пересчитывали все империи для каждого клиента и не задерживали команды. Любое изменение состояния, прав или ракурса инвалидирует её по sequence. Текущая диагностика скорости добавляется отдельно при каждой отправке; периодические снимки и heartbeat сохраняются.

Чтение stdout/stderr синхронного Triangle worker выполняется выделенными readers, чтобы занятый ожидающими сессию сетевыми обработчиками thread pool не мешал завершению pipes. Прежние timeout/kill/SHA/проверки результата сохраняются.

Лимит исходящего JSON остаётся 1 MiB. Для нескольких research empires повторяющиеся полные `unavailable` DTO передаются один раз в таблице внутри уже разрешённого research snapshot: `encoding=shared-unavailable-v1`, `unavailableTable`, `unavailableIndices` (массив ссылок для каждой империи в её исходном порядке). Полное равенство DTO включает gates/локализацию; одинаковый ID с разными полями не объединяется. Null и пустой список различаются, порядок и повторы сохраняются. Клиент раскрывает таблицу до использования snapshot, старый формат без encoding по прежнему принимается. Неизвестный encoding, несовпадение размеров, неверные/выходящие за пределы индексы отклоняются. Никакие данные не урезаются; таблица не содержит данных вне разрешённой проекции. Проверить lossless roundtrip, разные gates одного ID и общий ракурс наблюдателя на реальном WebSocket.
