### Bounded galaxy core and dust adaptation

Reference answer `01a13049-e023-73f0-8cb7-b5c4beb3efc0` and direct local inspection establish separate passes: `gfx/FX/galaxy_center.shader:56–57,74–76` places a horizontal plane at Y −1.5, expands XZ by 1.5 and samples its center texture ×0.5, with ONE/ONE blending and depth disabled. `galaxy_dust.shader:81–108,130–143` positions, sizes, rotates and tilts dust patches, multiplies the diffuse dust and color-map samples, then alpha blends with depth disabled. Source sampler behavior is linear, center/dust wrap, color map clamp. The shader also samples native terra incognita and border render targets; those runtime targets are unavailable and are not fabricated.

The exact file-to-sampler native binding and native patch distribution are not recovered. `gfx/map/center.dds`, `dust.dds` and `galaxycolor.dds` are explicitly selected browser bindings, an inference supported by source sampler roles and reference executable path strings. The importer first records their exact formats, raw channels, hashes, byte budgets and API. No original bytes enter Git. This small extension is necessary for the already authorized reference comparison, with no gameplay expansion.

Placement is static screenshot calibration: use only the authorized systems' AABB center and its maximum X/Z span (minimum 100), never private metadata, fleets or inferred undisclosed systems. Core is a single nonpickable horizontal square, width 0.55×span, centered at Y −1.5 relative to the authorized center, with half-intensity additive RGB. The initial 0.9-width GPU capture overfilled the fixture compared with R6; 0.55 reduces the visible bright core extent without changing native sample intensity. Dust is a fixed deterministic set of 24 nonpickable patches in three decorative arms, normalized radii 0.12–0.65×span, width 0.32×span, tangent rotation with source-style 0.1 tilt. It represents background art, not additional systems, territories or resources. Color-map UV uses the same authorized center and width 1.5×span. The whole decorative group is excluded from camera fit and picking, drawn over the source starfield and under lanes/markers. With no authorized systems it is omitted; filtered snapshots reveal no private extent. Shader channels remain raw NoColorSpace, an explicit browser sampling policy rather than a recovered native transfer function. Fog/borders are omitted for this public known-map fixture; no hidden intel field is inferred or transmitted.

Acceptance requires real imported textures, both galaxy presets at normalized canvas size, no generic procedural core/dust substitute, resource ownership/failed-stage disposal checks and independent review. Native binding, placement and transfer remain explicit limitations and reference/manual questions. Three arms and numeric widths are browser art calibration only; they do not alter topology.

Bounded core-transfer follow-up: compare current raw RGB with sRGB output, explicitly linearized source RGB with sRGB output, raw RGB without output encoding, and source-alpha-attenuated variants at identical far/near poses. Keep every other pass, source array, extent and blend factor fixed. Reference answer `01a13064-8af0-7013-84c2-410ea7a72ccd` verifies nonzero RGB outside the authored alpha footprint and native ONE/ONE without alpha attenuation; native upload and post-process routing remain unknown. Select a production correction only when paired actual-GPU captures visibly reduce the square footprint without losing the core. Source-alpha multiplication is permitted screenshot calibration, explicitly deviating from the authored shader; no arbitrary radial mask. Preserve resource ownership, picking and filtered bounds, and rerun relevant tests/review before delivery.

Selected core transfer after the paired GPU comparison: keep source storage `NoColorSpace` and linear filtering, then explicitly linearize the filtered core RGB with the piecewise sRGB EOTF (`c/12.92` below 0.04045, otherwise `((c+0.055)/1.055)^2.4`), multiply RGBA by 0.5 and retain ONE/ONE plus the renderer's sRGB output with no tonemapping. This supersedes raw core sampling above; dust/color and other passes remain raw as before. Alpha is sampled and halved but never multiplies RGB. This is a documented browser transfer assumption, not proof of native sRGB flags; it also does not claim hardware sRGB decoding before filtering. It reduces the broad rectangular footprint while retaining luminous detail in both poses. No alpha/radial mask or source mutation is selected. Exact HDR, TI, native pass routing and full reference similarity remain unverified.

Label safe area: `renderer.setLabelInsets({top,right,bottom,left})` accepts exactly four finite nonnegative CSS pixel values and owns a copy. Defaults are top/right/left 16 and bottom 72; UI may update measured overlay margins on resize/toggle. Label projection includes its measured text width and sprite height, and hides a label whose rectangle leaves the remaining area. Insets that exhaust a narrow viewport intentionally hide all scene labels and expose `stats().labelAreaEmpty=true`; the map, picking and camera still work. Galaxy fleet names are selection-only so S01 system names take priority. This clips labels against the HUD, not world objects; it cannot hide objects from the authorized projection.

## Контракт зависимости для импорта звезды — передать интегратору

Новые необходимые входы (не реализованы): `gfx/worldgfx/star_g_class.txt`, `gfx/worldgfx/lava_noise.dds`, `gfx/worldgfx/lava_d.dds`, `gfx/worldgfx/stone_d.dds`. Добавление только явных относительных путей одновременно в server manifest/allowlist/hash, browser profile и версию material profile; файлы игры/производные изображения в Git не попадают, shader-файлы не исполняются. Не расширять профиль автоматически на LUT/environment/sky/VFX.

- lava_noise: legacy DDS DXT1 cubemap, 1024², шесть граней, один mip. Проверять CAPS2 cubemap + все шесть face bits, square dimensions, точный payload, стандартный порядок +X/−X/+Y/−Y/+Z/−Z; orientation и seam подтверждать directional synthetic fixture. Частичные грани, volume/DX10/неизвестные layout, trailing/truncated payload — видимый отказ до allocations, без 2D fallback.
- lava_d: DXT5 2D 1024², 11 mips; stone_d: DXT1 2D 1024², 11 mips. Samplers: noise clamp, lava/stone wrap, linear filtering (`pdxmesh_samplers.fxh:69–95`). Color space каналов отдельно подтвердить; не объявлять весь DDS sRGB по имени.
- Decoded RGBA: cubemap 24 MiB; два base 2D по 4 MiB; весь набор base=32 MiB, со всеми исходными mips≈34.667 MiB. Это CPU typed arrays, не RAM/VRAM. Резервировать до распаковки и учитывать старую+staged сцены в существующих 512 MiB. GPU mips/драйвер считать отдельно, не создавать вторую decoded копию на каждый экземпляр звезды.
- Профиль владеет CPU arrays, GPU resource owner — сценой/профилем по существующему lifecycle. Общие textures переиспользуются; material.dispose не уничтожает borrowed textures. Отмена/ошибка импорта сохраняет прежнюю сцену и освобождает staged allocations; pagehide/context loss следуют существующему контракту. Ни сетевой передачи игровых bytes, ни постоянного кеша.

После передачи импортной работы возможен отдельный новый star material module: принимает только проверенные textures/явные uniforms, не читает диск/сеть, не ищет файлы, не вводит default для неизвестного native uniform. Поверхностный shader повторяет подтверждённую структуру lava/noise/stone/view dependence собственным GLSL; статический time выбран явно как адаптация существующего M3, анимация/VFX не добавляются автоматически. Неподдержанный вход — исключение до замены сцены. Подключение после CAM-коммита, профильной версии и ревью интегратора.

Независимый модуль `m3-star-material.mjs` возвращает параметры для Three.ShaderMaterial, без создания GPU-ресурсов. Обязательны borrowed lavaNoise/lavaDiffuse/stoneDiffuse; linear RGB bright/hot/cold; atmosphere RGBA/width/intensity; frozen noiseTime и uvOffset; column-major noiseBasis 3×3 для явной согласованной ориентации cubemap. None/default отсутствуют. Локальная позиция даёт направление sphere noise, world normal/world position — view dependence; только положительный uniform scale, без nonuniform/negative transform. Caller проверяет это до создания Mesh. Width/intensity/цвет атмосферы, color-space и noiseBasis не назначаются этим модулем и остаются интеграционной зависимостью. Результат непрозрачен, сохраняет depth и даёт линейный HDR RGB; native alpha=0 не переносится вслепую в Three framebuffer. HDR/bloom/LUT не воспроизводятся. GLSL содержит стандартные Three tone/color-space chunks; renderer выбирает общую политику. CPU-тесты проверяют контракт/отказ/borrowed ownership, но не компиляцию GPU или визуальное совпадение.

## Приёмка

### Renderer wiring contract

After the reviewed 49-file import commit is available, the exclusively owned `m3-world-renderer.mjs` may pass each validated sample to material creation. `PdxMeshStar` must require `sample.starSurface` and use `noisePath/lavaPath/stonePath`; missing metadata or decoded images fails staging and preserves the current profile/view. Cube creation uses `createDdsCubeTexture` from the import owner's adapter. The two 2D data textures use repeat wrapping and linear filtering/mipmaps, with NoColorSpace. Cache keys include path and sampler mode, and all instances borrow the profile textures/material. No new decoded pixel copy is allocated by the renderer. The existing old+staged decoded and converted-array budgets remain enforced.

Template entity scale, DTO scale, geometry attributes/indices, model origins, layer count/order, camera gestures, galaxy markers and simulation remain unchanged. Star atmosphere stays on the existing explicitly approximate rim adapter in this delivery: native culling/front-face conventions are not yet proven. The new surface shader changes neither atmosphere geometry nor unsupported VFX. The caller verifies positive uniform sample scale and finite original position/normal/UV inputs already required by the profile. Tests must cover star material selection, shared texture reuse, geometry/bounds preservation, rollback after bad metadata, and release of staged/retired GPU resources. The coordinator retains world-view, client entrypoint and project-file edits required for serving the new module.

Уточнение интегратора: добавляется 49-й обязательный путь `common/planet_classes/00_planet_classes.txt`, strict `pc_g_star` atmosphere HSV/intensity/width импортируются, не хардкодятся. Контракт импорта ведёт его владелец в M3-STAR-IMPORT.md. `createStaticGStarParameters(surface, textures)` преобразует импортированные HSV в RGB стандартной формулой, согласующейся с `standardfuncsgfx.fxh:184–196`, без sRGB transfer; считать выход линейным — явная политика адаптера M3, native CPU/uniform conversion не доказана. Интенсивность lava умножает соответствующий RGB. Surface atmosphere alpha=1, noiseBasis=identity, time=0 и uvOffset=0 — разрешённые статические адаптации M3, не доказанный runtime оригинала. Native `standard_vertex.fxh:23–24,89–90` под IS_STAR записывает в vTangent normalize исходной vPosition, а не атрибут mesh tangent. Наш noise direction совпадает с этой локальной величиной при identity noiseBasis и сохранении исходных positions/static bind pose; влияние skin/rotation исходной анимации не воспроизводится.

Входы GPU-модуля: lavaNoise — Three.CubeTexture, lavaDiffuse/stoneDiffuse — Three.DataTexture 2D с уже проверенными RGBA arrays. Другие texture subtypes не заменяют sampler2D; decoder/face validation остаётся обязанностью импортного профиля.
