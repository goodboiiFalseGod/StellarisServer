Server sample timestamps are monotonic ordering values, not synchronized UTC.

For `measured`, validate finite rate and denominator, integer count 0–512, window 2–10 seconds, nonnegative sample timestamp and the unrounded ratio `rate = count / windowSeconds` within the contract's absolute/relative `1e-9` tolerance. UI rounded values are checked against displayed precision, never against the wire tolerance. Other statuses must not display a current numeric rate; missing/unavailable is not measured zero. A full window is 10 seconds, not an assumed fixed denominator during warm-up or reset.

This includes bounded publication/transport uncertainty and is not a replacement for the runtime's completion timestamps. Compare like intervals: a final trailing-10-second reading must not be equated to an arbitrary whole-run average. Select observations spanning approximately that trailing window and also report the uninterrupted interval's overall average. Record actual endpoint gaps/receipt jitter; allow integer event-boundary uncertainty (normally at most one completion at each endpoint), plus measured timing uncertainty. Do not enlarge tolerance until a result passes. If gaps/latency prevent a defensible bound, mark the numerical cross-comparison inconclusive while retaining the exact count/window arithmetic check.
