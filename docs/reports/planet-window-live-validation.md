## Actionable finding: narrow colony entry obstruction (P2)

At **390×844**, approved observer in **player A POV**, paused galaxy, select personal outliner `Планета Система 1`. The selection card offers **Открыть колонию** (“Open colony”; `#open-planet`). A normal pointer click returns without opening `#planet-dialog`. Read-only hit test of its center returns **`section.identity-plaque[aria-label="Текущий вид и участник"]`** (“Current view and participant”), not the button. Button DOM bounds: **x=43, y=747, width=117.765625, height=28** (right=160.765625, bottom=775); center=(101.8828125,761). Exact plaque DOM bounds were not retained; [actual screenshot](../../content-local/references/planet13-narrow-open-obstructed.jpg) preserves the visible overlap. Keyboard Enter on the same button opens the correctly sized modal; this is only a workaround, not pointer acceptance.

Likely cause supported by source/layout: narrow `.selection-panel` uses fixed `bottom:68px`, while variable-height `.identity-plaque` includes observer POV/camera controls and overlays it at z-index 3. The occupied identity height is not reserved by the selection card. Risk: a visible primary colony-entry action receives clicks on a different element. Recommended bounded correction: reserve the actual plaque area or otherwise keep the selection action outside it, without moving command/privacy logic or changing native mechanics. This run did not compare the prior runtime, so whether the obstruction predates the new shell is **unknown**. Do not label it a newly introduced regression without that comparison. Root/UI owner owns any implementation and focused re-test scope; QA made no code fix.
