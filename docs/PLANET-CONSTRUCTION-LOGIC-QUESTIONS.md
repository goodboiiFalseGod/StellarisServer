# Отложенные вопросы логики строительства

14 октября 2026. Этот список отделён от консультации по вёрстке по прямому указанию пользователя. Вопросы не меняют геометрию меню и предназначены для одного пакетного ответа. Можно ответить `везде рекомендуемый вариант`, перечислив только исключения, либо дать ответы в формате `L01 — ...`.

## Нерешённые вопросы

Нет. Пользователь принял рекомендуемые варианты для всех оставшихся пунктов.

## Уже определено и сюда не возвращается

- Required work и оплаченная цена фиксируются при принятии заказа; текущая скорость применяется к ещё не выполненной работе без пересчёта уже накопленного progress.
- Полная фактически оплаченная стоимость возвращается при ручной отмене и известной потере условий независимо от progress; refund ограничивается storage caps. Уничтожение колонии возврата не даёт.
- Автоматическая отмена сообщает название заказа и конкретную известную причину. Прогресс начисляется ежедневно; остаток работы дня не переносится на следующий заказ.
- Обычная колония имеет одну активную позицию. Номады/Wilderness получают source-backed `N`; лишние активные заказы при уменьшении `N` приостанавливаются без потери progress.
- Параллельные завершения применяются последовательно в порядке очереди. Завершение строительства применяется до соответствующего месячного экономического расчёта.
- Районы можно заказывать повторно, пока завершённые и зарезервированные уровни не исчерпали вместимость. Exact building/zone slots резервируются и не принимают конкурирующий заказ.
- Zone replacement конфликтует только с заказами зданий затронутой zone occurrence; новая зона не открывает свои три building slots до завершения. Подтверждённые несовместимые здания удаляются без возврата.
- Устаревшие подтверждения и команды отклоняются без списания. Клиент получает новое авторитетное состояние и повторно показывает подтверждение только когда оно всё ещё требуется.
- Любая передача планеты отменяет все её заказы с возвратом исходным payer по общей политике; новый владелец не наследует очередь.
- Любой ставший неработоспособным заказ отменяется, освобождает reservation и получает возврат по общей политике. Неположительная скорость и внутренняя ошибка завершения не создают paused/error state; ожидание за пределами `N` остаётся обычным waiting state.
- Штатное завершение заказа отдельного уведомления не создаёт. При ручной отмене полный возврат без потерь также не показывается отдельным уведомлением.
- Уведомление об отмене открывает колонию и «Инфраструктуру», фокусируя сохранившуюся цель. Собственного игрового лимита длины очереди нет без source-backed правила.
- Потеря условий отменяет order сразу в породившей её транзакции. Исчезнувшему payer refund не перенаправляется и теряется с уведомлением. Уничтожение колонии создаёт одно сводное уведомление.
- При `N=0` очередь и progress сохраняются paused. Reorder меняет states сразу, progress начинается со следующей дневной фазы; внутри активного блока перестановка разрешена без потери progress.
- После upgrade/replacement/repair панель продолжает показывать target того же slot; при исчезновении slot/instance она закрывается без закрытия окна колонии.
- Несколько автоматических отмен одной колонии объединяются в одно уведомление с отдельными причинами. После ручной отмены показывается только фактическая потеря refund, если она была.
