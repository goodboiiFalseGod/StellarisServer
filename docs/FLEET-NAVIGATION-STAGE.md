#### Инженерное предложение system zoom-out — 13 октября 2026

Исследование без изменения runtime, база `f707706` (runtime `a2d47f8`). Это параметр презентации нашего клиента, **не факт native Stellaris**. До реализации предложение проходит независимое review и фиксируется коммитом. Исходники: `tools/asset-probe/m3-world-renderer.mjs` constructor/setCameraPreset/focusSelection/render/switchView/pointer handlers; `m3-camera.mjs:createCameraPreset`; `m3-navigation.mjs:ZOOM_THRESHOLDS/zoomDetail`; зафиксированный Three.js 0.186.1 `OrbitControls.js` из lockfile/локальной зависимости. Сетевой поиск native правил для этой клиентской калибровки не требуется.

Фактические пределы: renderer не переопределяет OrbitControls `minDistance=0`, `maxDistance=Infinity`, `enableDamping=false`; finite максимального zoom-out сейчас **нет**. Perspective near=0.01, far=max(10000, preset.distance×10) — clipping, а не ограничение zoom. System overview строится по received radius R и bounds [-R,-8,-R]..[R,8,R], FOV45°, direction(0,0.8,1), padding1.15, distanceScale0.8; aspect зависит от canvas. Автоматические system detail thresholds остаются near2.2R/far2.5R с hysteresis между ними; galaxy1.7/1.95 своих navigationScale. Возврат между видами не должен менять эти thresholds.

Один предлагаемый порог: **T = 1.5 × D_overview(R, aspect)**, где D_overview — расстояние существующего `system-overview` framing, вычисленное тем же `createCameraPreset` без применения к камере, по текущему received R и canvas aspect. Измеряемое d — Euclidean camera.position.distanceTo(controls.target), в единицах сцены. Никакого fallback R=150 при отсутствии/невалидности received R: переход недоступен с краткой причиной. При invalid aspect/distance/preset переход также не выполняется. 50% запаса от реального overview отделяют осознанное дальнейшее отдаление от обычного framing и near/far. Порог адаптируется к узкому viewport, в котором стартовый overview уже значительно дальше 2.5R; фиксированный 3R сразу находился бы внутри стартового narrow framing.

Проверенный расчёт существующей функцией для принятого fixture R=150: 1280×720 D=311.705485, T=467.558227 (3.117055R); 390×844 D=818.697900, T=1228.046851 (8.186979R); 390×400 D=439.406379, T=659.109568 (4.394064R). Это вычисление локальной калибровки, не новый gameplay radius и не browser/визуальный PASS; во всех трёх случаях T дальше current far-detail2.5R и ниже текущей far clipping10000. Применимость других R/aspect проверяется параметрическими cases, а не этими тремя примерами.

Триггер — только успешно обработанный native user zoom gesture на canvas в текущем system view: wheel (включая wheel trackpad/pinch), middle-button dolly или двухпальцевый touch dolly. OrbitControls обрабатывает wheel синхронно (start→update→end), deltaMode нормализует сам; middle/touch dolly также вызывают update. До обработки события захватываются d_before, system/view identity; после завершения его native handlers — d_after. Переход ровно один раз, когда **d_after > d_before и d_after >= T**. Поэтому инерция render/update, pan/Alt-orbit, нулевой wheel, zoom-in, ignored wheel при controls.disabled/active gesture, resize, snapshot/POV, preset/reset/focus, context/BFCache restoration и программный controls.update сами по себе не переходят в галактику. Если программная камера оказалась уже дальше T, она остаётся в системе до следующего реального outward gesture; это явно не требование пересечь T снизу. Pending event identity инвалидируется switch/preset/focus/resize/snapshot/POV/context-loss/dispose; после-event проверка не должна применять жест к другой системе или новой камере. Нельзя ставить постоянную проверку d>=T в render или общий controls change listener.

Возврат выполняет существующий showGalaxy/switchView, затем отдельный локальный callback `onSystemZoomOut()` синхронизирует client currentSystem=null/stressView=false и identity/controls/selection. Он не отправляет server command, не меняет command fleet/authoritative movement и не вызывает onOpenSystem. Galaxy wheel-in никогда не входит в system; explicit double-click/outliner entry сохраняется. Однонаправленный переход устраняет дрожание между видами; near/far hysteresis остаётся прежним. Cancel/reset native gesture выполнять после native input handler, чтобы не разрушить его обработку посередине.
