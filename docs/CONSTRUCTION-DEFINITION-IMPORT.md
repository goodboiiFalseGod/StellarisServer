# Строительные определения — проект технического контракта

12 октября 2026. Подготовка следующего среза, **не утверждение M4 и не реализованная функция**. Цель — отделить read-only импорт исходных определений от разрешения/исполнения строительства. Основания: [решения](DECISIONS.md), [аудит](reports/construction-next-slice-452.md), [ограниченное замыкание hydroponics](reports/hydroponics-import-dependencies-452.md). Принятый S18 не урезается до одного здания.

## Граница

Первый диагностический корень — `building_hydroponics_farm` 4.5.2. Выход содержит исходные числа, ссылки, условные ветви и покрытие; не готовую цену, длительность заказа или `CanBuild=true`. Никаких списаний, очередей, создания зданий/jobs и изменений M1/M2/M3. Ни строительство zones/districts, ни полный startup этим не реализуются.

Текущий `BuildingDefinition` содержит только upkeep/modifiers; его нельзя незаметно превратить в строительную модель. Используется отдельная immutable проекция, без зависимости от UI и с явной ссылкой на профиль источника.

## Данные проекции

- ID, относительный source/line/column и точная версия; manifest прочитанных зависимостей. Исследовательский список 22 SHA — свидетельства, не готовый runtime whitelist.
- Raw `base_buildtime`, верхняя category отдельно от economic `resources.category`, building sets, prerequisites, собственный upkeep.
- Cost — **упорядоченный список ветвей**, а не dictionary по ключу `cost`: исходник содержит два таких блока. Сохраняются trigger, resource, raw amount и отдельный raw `mult`. Нельзя вычислять итоговую стоимость по неизвестному scope или смешивать эту величину с upkeep.
- Potential/destroy/allow/abort и job-capacity inline — выражения с provenance и явным статусом поддержки. Отсутствующий блок не равен истинному разрешению общей механики. Capacity 200 не означает 200 занятых Pops.
- Для каждого поля: извлечено / требует runtime-контекста / неподдержано / исключено из этой проекции, с причиной. Успешный parse не означает исполнение выражения.

## Разрешение зависимостей и ошибки

Локальные переменные разрешаются до глобальных, с обнаружением циклов/отсутствия. Inline-подстановка сохраняет исходное место вызова и место определения; вложенные вызовы и циклы диагностируются. Сравнения, `owner`, `from?` и повторяющиеся блоки не теряются при нормализации AST. Неизвестное условие нельзя заменить false/true; regular и nomadic cost сохраняются раздельно. Формула optional scope требует отдельного доказательства до evaluator.

Чтение только из проверенного корня установки, точная 4.5.2, ограниченные размеры/объём/глубина и отмена. Лимиты ниже относятся к текстовому диагностическому профилю, не к бинарным ассетам M3. Traversal/reparse, missing/unreadable, неоднозначные definitions/overrides в прочитанных файлах, повреждённый UTF-8 и изменение источника между чтением и публикацией — видимый отказ без частичной проекции. Диагностика содержит относительные пути, не абсолютный локальный путь и не игровые байты. Ни исходные AST/скрипты, ни оригинальные файлы не передаются браузеру.

## API и фиксированный профиль диагностического импорта

Поручение координатора после интеграции bb9a7a2: реализовать этот read-only слой, без очереди и без изменения M1. API `ConstructionDefinitionImporter.ImportAsync(string gameRoot, CancellationToken)` возвращает `ConstructionProjection`; выбранный building ID и пути не принимаются от клиента. Типы в отдельном Content/Construction, importer не имеет изменяемого состояния между вызовами.

`ConstructionProjection`: GameVersion=`4.5.2`, ProfileId=`construction-hydroponics-452-v1`, Definition, Files и Coverage. `ConstructionDefinition`: Id, Origin, BaseBuildtime, Category, EconomicCategory, BuildingSets, Prerequisites, Upkeep, Costs и Fields. Amount содержит Resource/Value/Origin; cost содержит список Amounts, исходный Trigger и nullable RawMultiplier (null означает отсутствие поля, не вычисленный default). Fields — полный упорядоченный expanded AST выбранного определения: Key/Operator/Scalar либо Children, Origin и InlineCallSites. Сохраняются условия, неизвестные поля и сравнения; evaluator отсутствует. Числовые параметры inline разрешаются в контексте вызывающего файла до подстановки; дерево сохраняет место inline-definition и цепочку вызовов. Coverage различает extracted/context-required/unsupported/excluded, не заявляет полную поддержку farmers/triggers/technology. DTO не содержит абсолютных путей; все коллекции копируются и read-only, мутация через downcast не допускается.

Профиль читает launcher-settings.json, 03_resource_buildings.txt и три файла переменных из inventory (00_scripted_variables, 100_scripted_variables_zones, 10_scripted_variables_nomads). Inline-файлы загружаются только по достигнутым ссылкам внутри выбранного определения, под common/inline_scripts с безопасным относительным ID. Scripted triggers, jobs и technology остаются именованными runtime-зависимостями/coverage, не исполняются. Нет сканирования всей установки, override/DLC/mod load order и доказательства чистоты vanilla; ограничение явно в проекции. Сторонние определения не компилируются; неоднозначный hydroponics/одиночный scalar/global в прочитанном наборе отклоняется. Повторяющиеся cost/triggered modifiers разрешены как списки.

Пределы: launcher ≤1 MiB, иной файл ≤2 MiB, суммарно ≤8 MiB и ≤32 прочитанных файлов; синтаксическая вложенность ≤64 (проверяется до recursive parser и для итогового expanded дерева), inline-цепочка ≤16, цепочка переменных ≤32, expanded nodes ≤50 000. Пустые/absolute/colon/control/dot-сегменты путей и reparse в root/ancestor/зависимости отклоняются. Проверяются версия и hashes всех фактически прочитанных файлов повторно перед атомарным возвратом; cancellation соблюдается при чтении/разборе/раскрытии/повторной проверке. Для детерминированного synthetic mutation/cancel допустим instance-local internal seam перед повторной проверкой, только friend test assembly. Ошибки IO/parse оборачиваются безопасной относительной диагностикой без исходных байтов/inner exception с локальными путями; OperationCanceledException сохраняется. Inline math или неизвестный числовой синтаксис не вычисляется по догадке: в обязательных числах отказ, в некомпилируемых полях — unsupported с сохранением дерева.

`ContentSession` сейчас предоставляет AST/числа/проверку стабильности, но не доказывает эти гарантии: версия импортёра допускает 4.5.x, resolver лексический, повторные definitions отклоняются, DLC load order не реализован. Переиспользование требует явного адаптера/проверок; не менять legacy-семантику M1 попутно.

Дополнительный memory budget: сумма UTF-8 размеров expanded Key/Operator/Scalar ≤8 MiB, включая повторные inline-копии; размер подстановки проверяется **до** выделения результирующей строки. Node budget учитывает все expanded-копии, provenance ограничен inline depth и числом nodes. Это защита диагностического импортера от раздувания текста, не игровой параметр.

## Приёмка будущей реализации

1. Synthetic fixture: local-over-global, циклы/пропуски, две cost-ветви, порядок/operators, вложенный inline, отсутствие обязательной зависимости, unsupported condition без молчаливого default. Проверка immutable данных и отказа без частичного результата.
2. Реальная read-only 4.5.2: raw time 360, minerals 400 в regular-ветви; volatile_motes 400 с отдельным mult .1 в nomadic-ветви; upkeep energy 2; capacity 200; prerequisite tech_hydroponics. Эти числа не подтверждают итоговую цену, заселённость или доступность размещения.
3. Источник/отмена/privacy/reparse проверяются на synthetic fixtures; установка игры не меняется. Проверяются manifest и покрытие реально прочитанных ветвей; неполный closure отмечается явно.
4. Неизменность M1/M2/M3 проверяется подходящими существующими регрессиями после кода; отсутствие новых команд/UI подтверждает read-only границу.

## Что остаётся перед строительным runtime

Реальное состояние owner/planet/zone/занятости/технологий, свободные места, базовая capacity и её изменение, refund/rounding/cap, сочетание modifiers и дневной порядок. Прямые решения пользователя об оплате при заказе, резерве сразу и отмене сохраняются. Непроверяемые по текстам native-правила уже переданы в отложенную ручную приёмку; этот документ их не разрешает и не требует немедленного теста.
